## Что измеряется

Headless Chromium/Edge, окно 1280×900, Vite development, React StrictMode.
Счётчики добавляются только тестовым плагином Vite и считают выполнения функций
компонентов, включая двойные вызовы StrictMode. Это не число изменений DOM и не
замер времени загрузки в production. Два вызова при входящем сообщении относятся
к новой строке; свойства прежних строк остаются прежними.

API и WebSocket подменены локальной фикстурой: 50 сообщений, 26 комментариев,
задержка ответов 20 мс. Реальные сервисы и пользовательские данные не используются.
Повторное открытие выполняется в одной сессии, пока кэш свежий. После истечения
срока свежести, переподключения или ручного обновления запросы допустимы.
По этим результатам нельзя вычислить процент ускорения всего сайта: для этого
нужны отдельные замеры на сервере и устройствах пользователей.

## Запуск

В каталоге `zotgram`, после `npm ci` (Node с глобальным WebSocket, например 22+):

```sh
npm test
npm run lint
npm run build
npm run test:browser
npm run benchmark
```

Нужен установленный Edge/Chrome/Chromium. Если он не найден автоматически, задайте
`ZOTGRAM_BROWSER` с путём к исполняемому файлу браузера. Используются отдельные
профили в игнорируемом каталоге `.tmp`, личный профиль браузера не затрагивается.

Полный benchmark читает исходники двух предыдущих версий через `git show`,
не меняя рабочие файлы; соответствующие коммиты должны присутствовать в истории.
Он обновляет `latest.json`. Для проверки только текущей версии без обновления
отчёта: `npm run benchmark -- --current-only`.

Браузерная проверка использует предварительно собранный `dist`: мгновенный вывод
комментария, переход между страницами, ошибку и повтор с тем же ID, потерянный
ответ после успешной записи, удаление неудачной попытки, закрытие формы, счётчик
отдельного поста и выход из аккаунта во время отправки.

## Обновление сервера

Перед запуском обновлённого core примените миграцию `feed.0004_comment_send_attempt`
обычным для окружения способом (`python manage.py migrate` в сервисе core).
Она добавляет nullable UUID попытки и ограничение уникальности по посту, автору
и попытке. Старые комментарии и клиенты без UUID сохраняют прежнее поведение.
Повтор с тем же UUID возвращает уже созданный комментарий, в том числе после
потери HTTP-ответа. Во время разработки миграция проверена на тестовой БД;
рабочая БД не изменялась.

Очередь отправки хранится в памяти текущей сессии: переходы между страницами
её сохраняют, перезагрузка вкладки или выход из аккаунта очищают.
